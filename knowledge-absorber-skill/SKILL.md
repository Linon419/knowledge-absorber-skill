# 模式路由 (Mode Router)

本技能有两种输出模式，根据用户意图自动选择：

| 信号 | 模式 | 说明 |
|------|------|------|
| “分析”、”解析”、”存入知识库”、”深度分析” | **笔记模式 (Notes Mode)** | 生成完整教学文章（Markdown + HTML），即原有流程 |
| “学会”、”教我”、”教会我”、”我要学会这个”、”帮我搞懂”、”学习这个” | **教学模式 (Teach Mode)** | 交互式分块教学，一次只教一个知识块，每块后测试，直到全部掌握 |

**判断规则**：
- 如果用户意图不明确，**默认使用教学模式**（因为学会比拥有笔记更重要）。
- 用户可以随时切换：说”直接给我笔记”切换到笔记模式，说”一步步教我”切换到教学模式。
- 教学模式完成后，自动生成一份精简复习笔记（Markdown + HTML）作为学习成果物。

# 全局 0 基础教学法协议 (Zero-Beginner Teaching Protocol)

本技能默认读者是 **0 基础学习者**。无论进入笔记模式还是教学模式，都必须把复杂知识改造成一个可学习循环：

`学习地图 -> 最小知识块 -> 大白话直觉 -> 正式术语 -> 最小例子 -> 可观察锚点 -> 小动作练习 -> 观察记录 -> 低成本错误 -> 复盘升级`

## 0 基础教学循环

每个核心知识点按以下顺序处理：

1. **学习地图**：先说学完这一点能解决什么真实问题，以及它位于整套知识的哪一层。
2. **一句话结论**：用一句小白能听懂的话给出核心。
3. **大白话直觉**：用生活类比、图像、场景或已有经验搭桥。
4. **正式术语**：直觉建立后，再给英文术语、定义、公式或标准名称。
5. **最小例子**：用最小数字、最短代码、最小场景或最小图示跑一遍。
6. **可观察锚点**：指出学习者应该看哪个字段、图形、日志、界面、变量、K 线、输出或行为。
7. **小动作练习**：安排一个低风险动作，例如截图、标注、纸上推演、沙盒运行、最小仓位、最小输入。
8. **观察记录**：让学习者记录前后变化、意外点、变量变化和判断依据。
9. **低成本错误**：展示最便宜、最安全的失败方式，让学习者理解风险手感。
10. **复盘升级**：把这个知识块接到下一个更大的结构，形成螺旋式学习。

## 教学动作约束

- 先给整体用途，再讲细节。
- 每个自然段只推进一个关键概念。
- 新术语先用旧经验铺垫，再给正式名称。
- 所有公式、图表、代码、配置、字段都要接到可观察对象。
- 高风险领域先用模拟、截图、纸面推演、沙盒或最小安全规模。
- 每个知识块都要有一个“我现在能做什么”的小动作。
- 每个知识块都要有一个“哪里容易出错”的边界说明。
- 每个阶段都要通过案例复盘，把抽象规则变成判断力。

## 学会判定

只有当学习者能做到以下 7 件事，才算当前知识块通过：

1. 用自己的话说出一句话结论。
2. 在真实材料或界面中指出它在哪里。
3. 跑通一个最小例子。
4. 预测下一步会发生什么变化。
5. 说出最主要的错误方式。
6. 说出安全停止线或边界条件。
7. 解释它如何连接到下一层知识。

# 笔记模式核心流程 (Notes Mode Workflow)

本技能采用 **三级加载机制 (Level-3 Loading)** 配合 **真理锚定协议 (Truth Anchoring Protocol)**。请严格按照以下步骤执行。

## 第一步：智能摄取 (Content Ingestion)

先运行脚本获取干净的 Markdown 数据。脚本会自动清洗 HTML 噪音并处理多模态内容（PDF/OCR）。

1.  **运行摄取脚本**：
    - **Command**: `python [SKILL_PATH]/scripts/content_ingester.py "INPUT_URL_OR_PATH"`
    - **依赖自愈**: 运行前检查依赖。若发现 `ImportError`，**立即自动执行** `pip install -r [SKILL_PATH]/requirements.txt`，无需询问用户。

2.  **读取结果**：
    - 读取 `[SKILL_PATH]/config/raw_content.txt`。
    - 该文件已通过 `html2text` 清洗，可直接用于分析。
    - 如果输入对象是**本地代码文件、项目目录或仓库文档**，不要只依赖 `raw_content.txt` 的转写结果；必须继续打开关键源码、配置文件和相邻文档，恢复真实调用链与上下文。

## 第二步：真理锚定 (Truth Anchoring)

**“不要轻信任何文本，哪怕它看起来很专业。”**
在加载导师人格之前，必须先对摄取的内容进行**准确性校验**。

1.  **提取核心主张 (Claim Extraction)**：
    - 快速扫描 `raw_content.txt`。
    - **提取文件中提到的所有关键事实性主张**（Key Factual Claims）。
      - _重点关注_：具体数据、代码API用法、历史事件、绝对化论断（"总是"、"从未"）。

2.  **联网审计 (Web Audit)**：
    - **Tool**: 调用 `WebSearch`。
    - **Query**: 针对每个主张构造验证性搜索（例如："React 19 useEffect changes 2026"）。
    - **Constraint**: 必须包含当前年份（2026）以确保时效性。

3.  **生成校准报告 (Calibration Report)**：
    - 在心中构建一个“红队报告”。
    - 如果发现原文有误、过时或存在争议，**必须**在后续生成的教学笔记中显式标注。

## 第三步：覆盖建模 (Coverage Modeling)

在真正写作之前，先建立一个**隐藏的覆盖清单**，防止漏讲。

1.  **拆分源材料**：
    - 按标题、章节、代码块、表格、示例、警告框、定义段落拆分 `raw_content.txt`。
    - 如果是代码或项目分析，再按文件、类、函数、配置项补一层拆分。
    - 如果输入对象是 **notebook / 幻灯片 / 讲义 / 习题册**，必须再按 **cell、题目、图表、输出结果** 拆分；不能把整节内容压成一段“章节概览”。

2.  **建立覆盖清单**：
    - 在心中维护一个 `source unit -> must explain -> example/edge case -> status` 的映射。
    - `must explain` 至少包含：关键术语、核心机制、前置条件、边界条件、常见误解。

3.  **长文策略**：
    - 当源内容很长时，必须按章节/文件逐段分析，**严禁**只看开头和结尾就开始生成总结。
    - 当原文包含多个并列主题时，最终文章必须让读者看得出“每一块原文分别讲了什么、彼此如何连接”。

4.  **覆盖约束**：
    - 最终教学笔记必须覆盖所有重要 source unit。
    - 若确有省略，必须明确说明是“重复、次要、无关主线”中的哪一种，而不是静默跳过。
5.  **零基础降维约束**：
    - 默认读者是 **零基础、术语不熟、容易在中间步骤掉队** 的学习者，除非用户明确说明自己已经掌握前置知识。
    - 每个知识点必须执行全局 0 基础教学循环：`学习地图 -> 最小知识块 -> 大白话直觉 -> 正式术语 -> 最小例子 -> 可观察锚点 -> 小动作练习 -> 观察记录 -> 低成本错误 -> 复盘升级`。
    - 若篇幅或模式限制无法完整展开全部 10 步，至少保留：`解决什么问题 -> 大白话直觉 -> 正式定义 -> 最小例子 -> 可观察锚点 -> 常见错误/边界 -> 自检问题`。
    - 禁止使用”显然””不难发现””这里很简单””类似地可得”这类跳步句式；任何中间推理一旦可能让初学者断片，就必须补上。
    - 遇到公式、图表、代码、配置、数据列名时，必须逐个解释它们分别代表什么，而不是默认读者看得懂。
    - 如果原文隐含了前置知识，必须主动补一个简短的”前置知识兜底”解释，不能假设读者已经会。
    - 必须控制术语密度：同一小段不要连续抛出过多新词；引入新术语时，要先用旧术语或生活语言搭桥。
    - 如果用户明确说自己是零基础、看不懂、容易混乱，必须自动切换到”慢速教学模式”：段落更短、一次只推进一个新概念、每一小段末尾补一句”你现在只需要记住什么”。
    - 每个核心知识点都应尽量补齐”八件套”：一句话结论、大白话直觉、正式定义、最小例子、可观察锚点、小动作练习、常见错法、1 个自检问题。

6.  **幻灯片结构恢复（课程讲义特化）**：
    - 如果输入是课程讲义 PDF 或 PPTX，必须先识别页面类型：**标题页**（课程名/周数）、**内容页**（核心知识）、**图片页**（图表/示意图）、**过渡页**（章节分隔）。
    - 重建大纲层级：从标题页和过渡页提取章节结构，将内容页归入对应章节。
    - 过滤版权/logo 噪音：忽略重复出现的大学 logo、版权声明、页码等非知识性内容。

7.  **前置知识地图（课程讲义特化）**：
    - 扫描讲义内容，列出所有**隐含前置知识**（讲义假设学生已经会但没有解释的概念）。
    - 为每项前置知识标记优先级：`[必须先会]`（不会就完全看不懂后面的内容）或 `[最好先会]`（不会也能跟上但会吃力）。
    - 该地图将在模块 0 的”前置知识清单”中输出。

8.  **难度标定（课程讲义特化）**：
    - 为每个 source unit 标注难度等级：`[入门]`（看一遍就懂）、`[中等]`（需要停下来想一想）、`[硬核]`（需要反复读+练习才能掌握）。
    - 难度等级将在模块 0 的”学习路线图”和模块 2 的小节标题中输出。

## 第四步：加载导师人格 (Load Persona)

读取系统提示词以激活“首席认知架构师”人格。

1.  **加载 Prompt**：
    - **Command**: `cat [SKILL_PATH]/references/system_prompt.md`
    - **注意**：将读取到的内容作为 System Prompt 注入当前上下文。

## 第五步：生成教学内容 (Generate Content)

**本步骤适用于所有领域的知识（技术、国学、学术、商业）。**

根据 `raw_content.txt` 的内容、`system_prompt.md` 的指示以及**第二步的校准报告**，生成多模态输出。

1.  **结构化输出 (必填项)**：
    - **单一真理源**：文章结构、模块定义、透镜应用**严格遵循 `system_prompt.md` 中的 [Construct Narrative] 章节定义**。
    - **严禁偏差**：不要自行发明模块，也不要遗漏 System Prompt 中标记为 `[Mandatory]` 的任何部分。
    - **覆盖优先**：先满足“讲全、讲透、讲明白”，再考虑文风和排版。面对高密度材料时，允许文章更长，**不允许**为了短而牺牲细节。

2.  **深度下限 (必须满足)**：
    - 每个核心概念都要回答：`是什么 / 为什么重要 / 它如何工作 / 什么时候不成立或不该这样用`。
    - 每个核心术语、缩写、函数名、配置项、典故在**首次出现时**都要用大白话解释。
    - 每个关键机制都要拆成步骤、状态变化或因果链，不能只给结论。
    - 每个核心结论至少给出一个**具体例子、反例或边界案例**。
    - 每个核心知识点必须提供一个**可观察锚点**：读者应该看哪个字段、图、日志、代码行、输出、界面按钮、盘口字段、K 线位置或文档段落。
    - 每个核心知识点必须提供一个**小动作练习**：读者能立刻做一次标注、推演、运行、截图、模拟、复述或最小安全操作。
    - 每个核心知识点必须说明一个**低成本错误**：最常见的错法、最小代价的体验方式，以及如何复盘。
    - 遇到“更高效 / 更灵活 / 更安全 / 更先进”这类评价，必须补上机制解释与成立条件。
    - 每个小节都必须让零基础读者看得出：`它在解决什么问题 / 我为什么要学它 / 这一段看完后我应该会什么`。
    - 每个核心小节都应尽量提供一个“立即检查是否学会”的小问题或小任务，答案必须能从刚讲完的内容直接推出。

3.  **领域特化 (按类型追加)**：
    - **技术 / 代码**：必须交代入口、调用链、关键数据结构、状态变化、异常路径、性能或安全权衡。
    - **API / 产品文档**：必须交代前置条件、输入输出、成功路径、失败路径、版本差异、常见误用。
    - **论文 / 学术**：必须交代问题定义、假设、方法、数据/样本、指标、结果、局限性、为什么可信或不可信。
    - **国学 / 人文**：必须交代关键原句或概念、语境、历史背景、主流解释分歧、常见误读、现实启发。
    - **notebook / 数据分析 / 教学讲义**：必须按 cell 或步骤顺序讲解，说明每段代码在做什么、为什么此时做、运行后会看到什么、如果删掉或改掉会怎样；图表必须解释横轴、纵轴、每个图形元素代表什么、读图顺序、能得出什么结论、不能得出什么结论。
    - **练习题 / 作业题**：必须写出完整解题路径：`题目在问什么 -> 变量/数据类型判断 -> 为什么选这个方法/API/图 -> 代码怎么写 -> 结果怎么解释 -> 常见错法`，不能只给答案。

4.  **课程讲义慢速教学模式（自动启用）**：
    - 当输入对象被识别为**课程讲义（lecture slides/PDF/PPTX）**时，自动启用以下慢速教学规则，无需用户手动触发：
    - **一段一概念**：每个自然段只推进一个新概念，不要在同一段里塞多个新知识点。
    - **5 行以内**：正文段落尽量控制在 5 行以内，超过就拆分。让读者有"我在往前走"的节奏感。
    - **硬核前加温暖提示**：在标注为 `[硬核]` 的小节开头，必须加一段温暖提示（如"接下来这部分有点烧脑，但我会一步步拆给你看"）。
    - **每步都有回收**：每个小段末尾补一句"你现在只需要记住：……"。

5.  **生成与写入**：
    - 必须同时生成 Markdown 和 HTML 文件。
    - 写入位置：项目根目录下的独立文件夹 `knowledge_{YYYYMMDD}_{Title}/`
    - 文件名格式：`knowledge_{YYYYMMDD}_{Title}.md/html`
    - HTML 必须由 Markdown 作为**单一真理源**生成或严格同步改写，禁止出现 Markdown 与 HTML 内容深度不一致的双份手写版本。
    - **内容适配**：
        - **技术类**：使用 Preset A（现代清爽）。
        - **国学/人文类**：使用 Preset B（水墨清茶）。

# 教学模式核心流程 (Teach Mode Workflow)

当用户要求"学会"某个资料时，进入此流程。**核心原则：不要一口气输出，而是一步步教、一步步确认。**

## 教学第一步：摄取与拆块 (Ingest & Chunk)

1.  **运行摄取脚本**：同笔记模式第一步。
2.  **知识块拆分**：
    - 将 `raw_content.txt` 拆分为 **知识块 (Knowledge Chunks)**。
    - 每个知识块应该是一个**独立可学习的单元**：一个概念、一个流程、一个公式、一段代码逻辑。
    - 目标粒度：每块 **学习时间 2-5 分钟**，不要太大（学不完）也不要太碎（没意义）。
    - 建立知识块之间的**依赖关系**（哪些必须先学，哪些可以并行）。

3.  **生成学习路线图并展示给用户**：
    - 输出一个编号列表，展示所有知识块及其依赖关系。
    - 标注每块的难度等级 `[入门/中等/硬核]`。
    - 每个知识块都要标注：`学习目标 / 最小例子 / 可观察锚点 / 小动作练习 / 常见错法`。
    - 询问用户："这是学习路线，我们从第 1 块开始？还是你已经会某些部分，想跳过？"

## 教学第二步：逐块教学循环 (Teach-Test Loop)

对每个知识块，执行以下循环：

### A. 教 (Teach) — 使用 0 基础教学循环

每个知识块的教学内容控制在 500 字以内，并按以下压缩结构输出：

1.  **学习地图**：这块知识在解决什么问题，接到整套知识的哪一层。
2.  **一句话结论**：用小白能懂的一句话说核心。
3.  **大白话直觉**：用生活类比、图像或场景解释。
4.  **正式术语**：给出术语、定义、公式或标准名称。
5.  **最小例子**：用最小代码、数字、图示或场景跑一遍。
6.  **可观察锚点**：明确告诉用户现在应该看哪里。
7.  **小动作练习**：安排一个低风险动作，例如复述、标注、截图、模拟、改一个参数、跑一个最小输入。
8.  **低成本错误**：指出这个知识块最容易错在哪里，以及怎么用最小代价发现。
9.  **升级连接**：说明下一块知识如何从这里长出来。

**严禁**：
- 一次输出超过 500 字的教学内容（太长学生会走神）。
- 在一个教学块里塞多个新概念。
- 使用"显然""不难发现"等跳步句式。
- 只给解释，不给观察对象或练习动作。

### B. 测 (Test) — 主动回忆

教完后，**立即**向用户提一个问题，要求用户**用自己的话回答或完成刚才的小动作**。

问题类型（轮流使用，保持新鲜感）：
1.  **复述型**："用你自己的话解释一下，XX 是什么？"
2.  **应用型**："如果遇到 YY 情况，你会怎么用刚学的知识处理？"
3.  **辨析型**："XX 和 ZZ 有什么区别？"
4.  **预测型**："如果把代码中的 AA 改成 BB，会发生什么？"
5.  **反向型**："什么情况下 XX 方法会失败或不适用？"
6.  **观察型**："你在图/代码/界面/日志里应该看哪个位置？它变化说明什么？"
7.  **动作型**："按刚才的小动作做一次，你会记录哪三个变化？"

**格式要求**：
- 问题必须具体，不能问"你懂了吗？"（用户永远会说"懂了"）。
- 问题的答案必须能从刚教的内容中推出。
- 每次只问 **1 个问题**，等用户回答。
- 优先测试“能否观察到、能否做一个小动作、能否说出错法”，而不只测试概念复述。

### C. 判 (Judge) — 评估回答

收到用户回答后：

1.  **判断掌握程度**：
    - ✅ **掌握**：回答抓住了核心要点，即使措辞不完美。
    - ⚠️ **部分掌握**：方向对但有关键遗漏或误解。
    - ❌ **未掌握**：回答偏离核心或存在根本性误解。

2.  **反馈策略**：
    - ✅ → 肯定回答，补充一个小细节或边界情况，然后进入下一块。输出格式："✅ 对！[简短肯定]。补充一点：[一个细节]。我们继续下一块。"
    - ⚠️ → 指出哪里对了、哪里漏了，**用不同角度重新解释漏掉的部分**，然后再问一个**不同的问题**来验证同一个知识点。
    - ❌ → **不要说"错了"**，而是说"我换个方式再讲一遍"。用完全不同的类比/例子重新教，然后问一个更简单的问题。

3.  **最多重试 2 次**：
    - 如果同一个知识块经过 2 轮补充教学仍未掌握，标记为 `[待复习]`，先跳过往后教。
    - 在所有块教完后，**回头专门复习**这些待复习块。

### D. 进度跟踪

每完成 3-4 个知识块后，输出一次进度报告：

```
📊 学习进度：
✅ 已掌握：块1（概念A）、块2（概念B）、块3（概念C）
⚠️ 待复习：块4（概念D）
⬜ 未学习：块5-8
🎯 当前正确率：75%
```

## 教学第三步：综合测试 (Final Assessment)

所有知识块教完后：

1.  **打乱顺序**，从每个知识块中抽取 1 个问题，组成综合测试。
2.  一次给出 **全部问题**（不是一题一题问），让用户一起回答。
3.  批改后生成**成绩单**：
    - 每题的对错和简短点评。
    - 总体掌握率。
    - **薄弱知识块清单**：列出需要重点复习的块。

## 教学第四步：生成学习成果物 (Generate Artifacts)

测试完成后，自动生成：

1.  **精简复习笔记**（Markdown + HTML）：
    - 只包含核心知识点的"一句话结论 + 最小例子"，不需要完整教学文章。
    - 用户答错的知识点用 ⚠️ 标记，提醒重点复习。
    - 文件命名：`review_{YYYYMMDD}_{Title}.md/html`
    - 写入 `knowledge_{YYYYMMDD}_{Title}/` 文件夹。

2.  **薄弱点速查卡**：
    - 针对用户答错或部分掌握的知识块，生成简短的"错因 + 正解"卡片。
    - 附在复习笔记末尾。

## 教学模式质量验收

1.  [ ] 是否在开始前展示了学习路线图？
2.  [ ] 学习路线图是否为每块标注了 `学习目标 / 最小例子 / 可观察锚点 / 小动作练习 / 常见错法`？
3.  [ ] 每个知识块的教学内容是否控制在 500 字以内？
4.  [ ] 每个知识块是否按 0 基础教学循环压缩输出？
5.  [ ] 每个知识块是否包含可观察锚点和低风险小动作？
6.  [ ] 每个知识块后是否提出了具体的测试问题（而非"你懂了吗"）？
7.  [ ] 测试问题是否覆盖复述、应用、辨析、预测、反向、观察或动作中的一种？
8.  [ ] 是否根据用户回答给出了 ✅/⚠️/❌ 评估和针对性反馈？
9.  [ ] 未掌握的知识块是否用了不同角度重新教学？
10. [ ] 是否在最后进行了综合测试？
11. [ ] 是否生成了精简复习笔记和薄弱点速查卡？

# 何时调用 (When to use)

当出现以下任一场景时，请立即激活本技能：

1.  **显式学习指令**：
    - 用户明确要求：”学习这个”、”深度分析”、”解析链接”、”解释这个概念”、”存入知识库”。
    - 关键词触发：只要用户提到”学习”或”分析”配合某个对象，必须激活。
    - **教学模式触发**：”学会这个”、”教我”、”教会我”、”帮我搞懂”、”一步步教我”、”我要弄懂” → 进入教学模式。

2.  **复杂多模态输入**：
    - 用户提供了一个或多个 URL 链接。
    - 用户上传了文档文件（PDF, Word, Markdown, TXT）。
    - 用户上传了图片（PNG, JPG），且内容包含大量文字或图表。

3.  **代码深度解析**：
    - 用户选中或上传了代码文件，并询问：“这段代码是怎么跑的？”、“架构是怎样的？”。

4.  **隐式教学需求**：
    - 用户表示困惑：“我不理解这个概念”、“太难了，看不懂”。
    - 用户需要降维打击：“用大白话解释一下”、“给个小白能懂的例子”。
    - 用户希望把任何复杂主题按 0 基础路径学习：“从零教我”、”零基础学这个”、”给我学习路线”、”把这个拆成练习”。
